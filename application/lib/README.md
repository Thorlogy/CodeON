# Checked-in Java runtime dependencies

This directory contains the versionless runtime JAR set used by the packaged
CodeON application. It is generated by the Maven build configured in
`OpenRobertaServer/pom.xml`; it is not an independently maintained collection.

## Current build

- Project version: `5.3.0-SNAPSHOT`
- Last complete dependency-set refresh: 2026-07-30
- Source: the CodeON multi-module Maven build on `master`
- Expected checked-in files: 91 JARs, consisting of seven project JARs and 84
  third-party runtime JARs

The project JARs are `OpenRobertaRobot.jar`, `OpenRobertaServer.jar`,
`RobotApitor.jar`, `RobotCozmo.jar`, `RobotEdison.jar`, `RobotRCX.jar`, and
`RobotSpike.jar`. Maven removes dependency version suffixes when it assembles
the server resource directory, so the versionless names alone are not evidence
of the dependency versions. The verified versions are recorded in the root
`ListOfThird-PartyProductsAndLicenses.txt` and can also be read from the JAR
metadata.

## Regeneration

From the repository root, using the Java and Maven versions required by the
project:

```bash
mvn -pl OpenRobertaServer -am clean install -DskipTests

# Review the newly assembled set before replacing the checked-in files.
find OpenRobertaServer/target/resources -maxdepth 1 -name '*.jar' -print | sort
find application/lib -maxdepth 1 -name '*.jar' -print | sort

# After review, replace the complete set so removed dependencies cannot linger.
rm application/lib/*.jar
cp OpenRobertaServer/target/resources/*.jar application/lib/
```

Then verify the count and project versions:

```bash
find application/lib -maxdepth 1 -name '*.jar' | wc -l
for jar in application/lib/OpenRoberta*.jar application/lib/Robot*.jar; do
  unzip -p "$jar" 'META-INF/maven/*/*/pom.properties' 2>/dev/null |
    grep -E '^(groupId|artifactId|version)='
done
```

Commit regenerated JARs together with the Maven dependency change and update
the date, count and license inventory in this README and the repository root.
